# Sentinel 13.9.176

Base: production commit e4b5f606b77e520047243ef98e07a56f245a6fb6, including 13.9.175 and the R$289 / US$60 commercial updates. The published 168 remains the reference for preserved admission, not a wholesale rollback of browser fixes.

## Resulting behavior

A range-turn proposal cannot sell a shallow retreat into independently mapped support, or buy into mapped resistance, while the received price leg still advances against it and has no local structural turn. A continuation retesting a previously rejected opposing level without clearing it is reviewed at the actual current price. Mere proximity does not reject an entry; fresh breaks and independently confirmed fast reversals retain authority. The same pure received-price review accepts only 30s, 1m and 5m inputs, with observation spans scaled to the holding period. Five-minute admission remains reversal-only.

The additional 173 rule demanding a break/retest for an otherwise significant new PUT low is removed: the exact 168 floor rule is restored. The 175 late-position review, 1450ms quote freshness, 172 own-fast-reversal confirmation and 170 old-continuation contradiction review remain. The fast-reversal detector, observed-level-sequence detector and runtime are byte-identical to the production base. No candidate queue, fixed entry-second cutoff, additional subscription, timed market wait or automatic opposite-side trade is introduced.

Native expiry revision 13 reads labelled composite clocks and unambiguous selected-value descendants. It also handles a newly opened portal's options and persists exact trusted selections, including explicitly selecting 30s. Chart-period revision 4 restores newly opened portal options independently of order expiry. Existing permission renewal, immediate-reload persistence, busy-click exclusion, broker-origin validation and manual-choice precedence remain. An automatic order with a required duration is refused before a click if the native value is absent, unrecognized, repairing or different. Preference alone no longer certifies broker expiry; startup and read-only observation remain available.

The secondary live reading retains its row during text updates. PC uses theme-aware blue, 11px semibold text and 15px line height. The React card uses theme-aware blue, 12px semibold text and a separate full-width row. No countdown, receipt or decision permission is changed by presentation.

## Validation and limits

798 existing and new prebuild tests passed. Production Next.js build and type checks passed. Isolated Chromium covered both providers, labelled/split clocks, portal pickers, immediate reload for all three durations, a busy executor, permission renewal and a child frame. Actual React rendering at 360px and 1280px verified stable countdown position for changing secondary text in all three durations. The PC operation-in-progress card retained constant height and the intended font/color. No live broker orders were placed.

Paired snapshots use only data present at each recorded decision. Across 114 instants from the 160, 168, 170 and 175 datasets, the candidate retains all 55 winning decisions admitted by 175, restores three previously withheld recorded winners and also restores one recorded loss from the older 160 dataset. It additionally refuses 175 entries 3 and 4, both recorded losses. The 5th and 8th recorded losses remain admitted; this is not a claim to have eliminated losses. Compared with 168, its older 1m quotes remain subject to the already-published 1450ms freshness rule (three old recorded winners fall outside it).

A separate bounded causal reconstruction after refusing 175 entry 3 found a fresh, independently qualified CALL rejection four seconds later. After entry 4 it found another qualified setup 47 seconds later. This is a check against immediately reissuing the refused signal, not an executed-trade backtest: subsequent live state, fills and expiry cannot be inferred as broker results.

Only 1m trades were present in the latest ZIP. Actual 30s/5m results and the user's native picker after its real reload still require live observation. The ZIP did not contain the actual native control DOM. Browser coverage verifies the supported layouts and prevents unknown values being silently accepted; it does not prove every broker skin is recognizable. There is no calibrated future WIN probability or guaranteed win rate.
