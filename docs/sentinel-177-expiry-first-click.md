# Sentinel 13.9.177: first-click expiry regression and compact card

Base: published 176, commit ec4b656b5fd4427e850c9a31d71f57db1d8b1f43, tree e3f0e329e1e312f1a1bc9c9c2c405f8f5774b5e1.

176 incorrectly made a recognized native expiry value a prerequisite for every automatic order. The user's actual broker leaves that control unidentified; timing information may arrive only in the broker acknowledgement after a click. Requiring that observation before the first click creates a bootstrap dependency. 177 removes ONLY the unknown-value / missing-keeper rejection. Unknown remains null and is not presented as a validated native duration. A known conflicting duration and a repair already in progress still prevent a click. Restoration, persistence, permission renewal, manual selection and broker acknowledgement handling remain. Native revision 14 additionally recognizes ordinary duration buttons under a compact visible Tempo label, without relying on a CSS class containing expiration. Chart revision 5 recognizes localized candle-period controls and their immediate chart toolbar context. Candidate fields still need an exact supported duration; clocks/countdowns and ambiguous controls are excluded. Actual recognition of the user’s broker skin is not established by an isolated fixture. The corrective first-click contract supersedes the stricter contract documented for 176.

The PC secondary line keeps its blue 11px semibold text but reserves one 15px line, expanding naturally for longer text. Grid gaps/padding and the countdown's unused minimum space are reduced. All fields, font sizes, actual clocks, prices and WIN/LOSS counts remain. React uses a 16px minimum secondary line and a smaller direction-block minimum. No clipping, ellipsis or line clamp is added: long secondary messages wrap and remain visible. Ordinary one-line observations remain stable; longer content is allowed the height it needs.

No market decision module is changed from 176. This release does not change reversals, continuations, signal timing, probability, or 5m eligibility. No broker orders are placed during validation. First-click tests cover both providers and 30s/1m/5m, with an unidentified native field, one simulated click, no invented accepted order and null native duration. Existing known-mismatch and reload tests remain required. Isolated browser tests compare 176/177 card height, verify all operation fields and require long text to fit without hiding.

Validation: 808 prebuild tests passed, including actual executor-path simulated first clicks on both providers for all three durations. Next.js build and types passed. Isolated reload tests passed for both providers and 30s/1m/5m. PC active-card comparison measured 237px in 176 versus 222.375px in 177 for the same one-line reading and full operation fields; longer text wraps visibly instead of being hidden. Actual React rendering at 360px and 1280px verified that only wrapped text adds height. No market-decision source file differs from 176. The user's live browser could not be inspected; these tests do not establish that the real reported 30s reset has been eliminated on that broker skin.
